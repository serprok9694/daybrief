# daybrief — PRD

> Статус: v1, согласовано 2026-10-27 (интервью-грилинг).
> Этот документ — источник правды для решений по продукту. Агенты-разработчики читают его перед любой задачей; изменения решений фиксируются здесь и в ADR (`docs/adr/`).

## 1. Суть

**daybrief** — персональный дашборд «мой день»: одно место, куда заходишь утром и видишь всё важное о себе на сегодня — события, задачи, важные письма, идеи, к которым пора вернуться, и короткую AI-сводку дня.

**Долгосрочное видение:** персональный ассистент в духе Jarvis. Дашборд — первый слой; поверх него позже появляется текстовый, затем голосовой агент, который умеет не только показывать, но и действовать («перенеси встречу», «ответь, что опоздаю»).

**Формат проекта:** сайд-проект с потенциалом вырасти в платный продукт (веб + мобильное + десктоп приложение).

## 2. Пользователи

- **v1:** только автор (dogfooding).
- **Архитектура — сразу multi-tenant:** авторизация, пользовательские подключения аккаунтов, изоляция данных по пользователю (Supabase RLS). Чтобы открыть продукт другим людям, не нужен рефакторинг.

## 3. Критерий успеха v1

Автор **2 недели подряд** открывает daybrief каждое утро вместо того, чтобы отдельно проверять календарь и почту.

## 4. Скоуп v1

### 4.1 Экран

Один экран — дашборд — плюс настройки (вход через аватар). Боковой навигации и нижних табов в v1 нет: добавим, когда появится второй раздел.

### 4.2 Блоки дашборда

| Блок | Источник | Что показывает |
|---|---|---|
| **Приветствие** | — | «Good morning, {name}» + дата |
| **AI-сводка дня** | все блоки + LLM | 2–3 предложения: «Сегодня 4 встречи, первая в 10:00. 2 важных письма ждут ответа. С 14 до 16 свободно» |
| **События сегодня** | Google Calendar | Таймлайн событий дня; текущее/следующее выделено; ссылка на Meet/Zoom; клик → событие в Google Calendar |
| **Задачи** | Google Tasks | Задачи со сроком сегодня + просроченные; клик → Google Tasks |
| **Важные письма** | Gmail + LLM | Письма, которые LLM счёл важными: отправитель, тема, выжимка 1–2 строки, пометка «нужен ответ»; клик → письмо в Gmail |
| **Идея дня** | Идеи + Calendar + LLM | Одна идея, предложенная под свободное окно; кнопки «Не сейчас» / «Готово» |
| **Командная строка** (верх) | — | В v1 — быстрый ввод идеи. Позже — вход в Jarvis (то же место, тот же вид) |

У каждого виджета — своя кнопка «обновить».

### 4.3 Принцип read-only

Дашборд **только читает** данные Google и ведёт ссылками в исходный сервис. Никаких записей в Google в v1.
**Исключение:** состояние идей («не сейчас» / «готово») — хранится в нашей БД, в Google не пишется.
Действия над данными Google появятся вместе с агентом.

### 4.4 Идеи

Автор записывает идеи в Apple Notes / Reminders (у них нет веб-API). Поэтому идеи попадают в daybrief тремя путями:

1. **Командная строка** в daybrief.
2. **Apple Shortcut «Send to daybrief»** — из share sheet (выделенная заметка) и через Siri («идея для daybrief …»).
3. **Apple Shortcut-автоматизация** — раз в день читает список напоминаний «Ideas» и отправляет новые пункты.

Для (2) и (3): эндпоинт `POST /ideas` + персональный API-токен пользователя (создаётся/отзывается в настройках). Дедупликация по внешнему id / хэшу текста.

**Подсказка идеи:** раз в день при сборке утренней сводки LLM смотрит календарь; если есть свободное окно ≥ 1 часа — выбирает одну давно не тронутую идею и формулирует предложение («У тебя свободно с 14 до 16 — может, поисследовать X?»).
- «Не сейчас» → идея скрыта на 7 дней.
- «Готово» → идея архивируется.

Когда появится iOS-приложение, оно будет читать Reminders напрямую (EventKit).

### 4.5 Почта

- Подключается **отдельно** кнопкой «Подключить почту» в виджете писем (не при логине): меньше пугающих разрешений на входе, и restricted-scope Gmail изолирован от остального продукта.
- Новые письма разбираются LLM **один раз** при синхронизации: важно/не важно, нужен ли ответ, выжимка 1–2 строки.

### 4.6 Языки

Интерфейс — **английский и русский** с переключением в v1 (i18n с первого коммита). AI-сводки и выжимки пишутся на языке интерфейса пользователя.

## 5. Вне скоупа v1 (осознанно отложено)

- **Здоровье** — Google Fit API закрывается; Apple Health / Android Health Connect доступны только on-device → вместе с мобильным приложением.
- **Агент (текстовый, затем голосовой)** — следующий этап после v1. Слой данных v1 проектируется так, чтобы агент вызывал его как tools.
- **Действия над данными Google** (ответы, перенос встреч, отметка задач).
- **Другие экосистемы:** Microsoft (Outlook/To Do), Apple Calendar.
- **Погода, новости и прочие внешние виджеты.**
- **Монетизация, онбординг для внешних пользователей, прохождение Google verification.**
- **Мобильное и десктопное приложения** — архитектура готова, сборки позже.

## 6. Архитектура

### 6.1 Стек

| Слой | Решение | Почему |
|---|---|---|
| Монорепо | pnpm + Turborepo | Общая логика/типы между приложениями |
| Клиент | **Expo** (React Native + react-native-web, Expo Router) | Один UI-код на web/iOS/Android; Apple Health позже без отдельного проекта |
| Стили | NativeWind | Tailwind-подход на всех платформах |
| Десктоп | Electron-обёртка web-сборки (позже) | |
| Auth + БД | **Supabase** (Auth, Postgres, RLS) | Быстро, Google OAuth из коробки |
| API | **Hono** на **Vercel** | Переносимость (Node/Bun/CF — для будущего агента со стримингом), RPC-клиент с end-to-end типами, общий middleware |
| Фоновые задачи | Supabase `pg_cron` + `pg_net` → защищённый эндпоинт sync на Vercel, каждые 10–15 мин | Без Vercel Pro; позже можно перейти на очередь (Inngest/QStash) |
| LLM | Claude API, `claude-haiku-5-5` для разбора почты, сводки и подсказок | Дёшево (~$0.10/$0.50 за MTok); дорогие модели — для будущего агента |
| i18n | en + ru с первого дня | |

### 6.2 Структура репозитория

```
apps/
  app/          ← Expo: web + iOS + Android
  desktop/      ← Electron (позже)
  api/          ← Hono на Vercel: sync, LLM, /ideas, RPC для клиента
packages/
  core/         ← доменная модель и типы: Event, Task, ImportantEmail, Idea, DayBrief
  connectors/   ← google-calendar, gmail, google-tasks (чистые функции: токен → доменные объекты)
  ui/           ← общие компоненты и дизайн-токены
  i18n/         ← словари en/ru
docs/
  PRD.md
  design/       ← бриф для Claude Design, референсы, итоговый дизайн
  adr/          ← решения
```

Ключевое: `core` и `connectors` — единый слой данных. Дашборд и будущий агент читают через него одно и то же; функции коннекторов в будущем оборачиваются в tools агента.

### 6.3 Поток данных

1. Пользователь входит через Google (Supabase Auth) — при входе запрашиваются scopes Calendar (read) и Tasks (read).
2. Refresh-токены Google сохраняются **зашифрованными** в БД.
3. `pg_cron` каждые 10–15 мин вызывает `POST /internal/sync` (секрет в заголовке) → API обходит пользователей, тянет изменения из Google, новые письма прогоняет через LLM, пишет результат в Postgres.
4. Раз в день (утро по таймзоне пользователя) — сборка AI-сводки и подсказки идеи.
5. Клиент читает готовые данные из API — дашборд открывается мгновенно. Кнопка «обновить» на виджете запускает sync конкретного источника.

### 6.4 Данные и приватность

- **Тела писем не храним.** Только метаданные (отправитель, тема, ссылка, дата) + LLM-выжимка; выжимки удаляются автоматически через 7–14 дней.
- События и задачи кэшируются коротко (для дашборда «на сегодня»).
- Google-токены — зашифрованы; ключ шифрования и `ANTHROPIC_API_KEY` — только в секретах окружения, никогда в клиенте и в репозитории.
- RLS на всех пользовательских таблицах.
- Чем меньше чувствительных данных храним, тем проще будущий security assessment Google и тем сильнее продуктовый аргумент «мы не храним твою почту».

### 6.5 Внешние ограничения (факты)

- **Gmail `gmail.readonly` — restricted scope.** В testing-режиме: до 100 тестовых пользователей, повторная авторизация каждые 7 дней. Для публичного запуска — Google verification + ежегодный платный security assessment.
- **Vercel Hobby:** cron не чаще раза в день → поэтому планировщик — `pg_cron`.
- **Claude API** оплачивается отдельно от подписки Claude (ключ из Claude Console). В Console выставлен месячный лимит расходов (например, $10).
- **Apple Notes/Reminders, Google Keep (личный)** — без публичного API.

## 8. Процесс разработки

- Код в GitHub-репозитории `daybrief`, локально — `~/Projects/daybrief`.
- Автор — продакт и ревьюер; код пишут агенты Claude Code.
- Работа идёт через GitHub issues → PR с тестами → ревью → merge.
- Контекст для агентов: `CLAUDE.md` (правила проекта), этот PRD, ADR в `docs/adr/`, глоссарий доменных терминов.
- Каждая задача должна быть проверяемой: тесты + понятный критерий «готово».

- Когда и как проходить Google verification для Gmail.
