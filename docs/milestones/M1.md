# M1 — Календарь

> Цель: на дашборде видны реальные события на сегодня из Google Calendar, и они сами обновляются в фоне.
> Контекст: [`../PRD.md`](../PRD.md) (6.3 поток данных, 6.4 приватность), дизайн — [`../design/README.md`](../design/README.md) («Таймлайн события», «Состояния виджетов»), макет — `../design/source/EventsWidget.dc.html`. Хвосты M0 — в [`M0.md`](M0.md).
> Каждая задача ниже = один PR. Агент начинает с чтения PRD, design README и этого файла.

## Решения для M1

| Тема | Решение |
|---|---|
| Какие календари | Все календари со `selected: true` в `calendarList` (то, что пользователь видит в Google Calendar). События со статусом `cancelled` и те, где пользователь ответил «нет», не показываем |
| Окно синхронизации | «Вчера + сегодня + завтра» в таймзоне пользователя (`profiles.timezone`). Каждый sync перезаписывает события в окне целиком; `syncToken` не используем (он не работает с `timeMin/timeMax`, а окно маленькое) |
| Что храним | Только то, что показывает виджет: id, календарь, начало/конец (`timestamptz`) или дата (весь день), название, ссылка на видеозвонок, `htmlLink`. **Описания, участников и вложения не храним** (PRD 6.4). Всё старше вчерашнего дня удаляется при sync |
| Access token | В БД — только зашифрованный refresh token (M0). Access token получаем при каждом sync через `oauth2.googleapis.com/token` (`GOOGLE_CLIENT_ID/SECRET`), нигде не храним. `invalid_grant` → `google_connections.status = 'revoked'`, другие ошибки Google → `'error'` + текст в состоянии sync |
| Фоновый sync | `pg_cron` каждые 15 мин → `pg_net` `POST /internal/sync` с заголовком `x-sync-secret`. Секрет — в Vercel env (`SYNC_SECRET`) и в Supabase Vault. API обходит всех пользователей с активным подключением, по одному, с таймаутом на пользователя |
| Ручное обновление | Кнопка «обновить» в виджете → `POST /sync/calendar` (только свой пользователь). Не чаще раза в 30 с на пользователя, иначе отдаём текущие данные |
| Чтение | `GET /events/today` → события сегодняшнего дня пользователя, `syncedAt`, ошибка последнего sync. Клиент считает «следующее событие» и «через N мин» сам по своим часам |
| Свободные окна | Чистая функция в `packages/core`: промежутки ≥ 1 ч между событиями в рабочих границах **09:00–21:00** локального времени, начиная не раньше «сейчас». Её же переиспользует M4 для подсказки идеи |
| Ссылки | Клик по событию → `htmlLink` в Google Calendar; Meet/Zoom — из `hangoutLink` / `conferenceData`, иначе первая ссылка Zoom/Meet/Teams в `location` |

## T0 — Настройки Google и Vercel *(делаешь ты)*

- Google Cloud → APIs & Services → Library → **Google Calendar API → Enable** (и сразу **Google Tasks API** для M2).
- Vercel `daybrief-api` → Environment Variables (Production **и Preview**):
  - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — из Google Auth Platform → Clients (тот же клиент, что в Supabase);
  - `SYNC_SECRET` — `openssl rand -base64 32`, сохранить и в локальный `.env`;
  - заодно добавить Preview к `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `TOKEN_ENCRYPTION_KEY` (хвост M0: вход на preview).
- Supabase → SQL Editor: положить тот же секрет в Vault — команду даст T3.

**Готово, когда:** API включены, переменные заданы, сделан Redeploy `daybrief-api`. Секреты в чат и в репозиторий не попадают.

## T1 — Модель событий и коннектор Calendar

- `packages/core`: тип `CalendarEvent` (id, calendarId, title, start/end или allDay date, videoUrl, htmlLink), `TodayEvents` (события, `syncedAt`, `error`); функции `todayRange(timezone, now)`, `freeWindows(events, now, timezone)` (правила — в таблице решений), `nextEvent(events, now)`.
- `packages/connectors/google-calendar`: чистые функции, `fetch` передаётся параметром:
  - `refreshAccessToken(refreshToken, client)` → access token / ошибка `revoked` | `error`;
  - `listSelectedCalendars(token)`;
  - `listEvents(token, calendarId, range)` с пагинацией → `CalendarEvent[]` (маппинг: весь день, отмены, отказ пользователя, видео-ссылка, без описаний и участников).
- Тесты на фикстурах реальной формы ответов Google (события на весь день, через полночь, повторяющиеся `singleEvents=true`, отменённые, отказ, Meet/Zoom), на `freeWindows` и `todayRange` (смена DST, Europe/Warsaw и UTC).

**Готово, когда:** тесты зелёные; в коде коннектора нет сети без переданного `fetch`.

## T2 — Хранение, sync и API событий

- Миграция: `calendar_events` (user_id, calendar_id, event_id, поля из T1, synced_at; PK user_id+calendar_id+event_id) и `sync_state` (user_id, source `'calendar'`, synced_at, error, locked_until). RLS: пользователь читает только свои строки, пишет только service role.
- `apps/api`:
  - сервис `syncCalendar(userId)`: расшифровать refresh token → access token → календари → события окна → в транзакции заменить события окна и удалить старше вчера → обновить `sync_state`; статус подключения по правилам из таблицы решений;
  - `POST /internal/sync` (проверка `x-sync-secret` за постоянное время; обход активных подключений; итог — счётчики, без данных пользователей);
  - `POST /sync/calendar` (JWT, лимит 30 с через `locked_until`);
  - `GET /events/today` (JWT).
- Тесты с фейковыми deps: успешный sync, `revoked`, ошибка Google, лимит частоты, неверный секрет → 401, ни один ответ и лог не содержит токенов.
- Новые env — в `.env.example` и `docs/deploy.md`.

**Готово, когда:** миграция применяется локально; тесты зелёные; после merge `POST /sync/calendar` на проде заполняет `calendar_events` для автора (проверка — SQL-запрос из PR).

## T3 — Фоновое расписание

- Миграция: `pg_cron` + `pg_net`; job `daybrief-sync` каждые 15 мин вызывает `POST https://daybrief-api.vercel.app/internal/sync`, секрет читается из Vault (`vault.decrypted_secrets`), не хранится в тексте миграции.
- Инструкция для пользователя в PR и в `docs/deploy.md`: одна SQL-команда `vault.create_secret(...)` в SQL Editor.
- Как проверить: `cron.job_run_details` и `net._http_response` (статус 200), рост `sync_state.synced_at`.

**Готово, когда:** на проде job отрабатывает по расписанию 2 раза подряд с ответом 200.

## T4 — Виджет «События»

- По `EventsWidget.dc.html` и «Таймлайн события» в design README: время (tabular) + длительность, линия с точками, название, чип Meet/Zoom с иконкой `video`; следующее событие — `--accent-soft`, точка с кольцом, сплошной чип «через N мин»; свободное окно ≥ 1 ч — пунктирная строка «Свободно 14:00–16:00»; события на весь день — сверху отдельной строкой.
- Состояния: загрузка (4 skeleton-строки — уже есть), пусто («Сегодня без встреч — день твой»), ошибка («Не удалось обновить» + «Повторить»), «Обновлено N мин назад», «Показать ещё N» после 5 событий.
- Данные из `GET /events/today`; кнопка «обновить» → `POST /sync/calendar`, потом перечитать; автообновление при возврате на вкладку, если данным > 5 мин. «Через N мин» и выделение следующего пересчитываются раз в минуту.
- Если подключение `revoked` / `error` — состояние ошибки с подсказкой переподключиться в настройках.
- Строки — i18n (en + ru, ICU-плюралы для минут/часов); dev-мок расширить сценариями: обычный день, пусто, ошибка, много событий, события на весь день.

**Готово, когда:** виджет совпадает с макетом на 1440 и 390 в обеих темах и языках (dev-мок); lint, typecheck, test, build зелёные.

## T5 — Финальная проверка M1 на проде

- Сценарий: в Google Calendar на сегодня есть 3+ события (одно с Meet, одно на весь день) → дашборд показывает их в правильном порядке и таймзоне, следующее выделено, свободное окно видно → добавить событие в Google → через ≤ 15 мин (или по кнопке «обновить») оно появилось → удалить → исчезло.
- Проверить, что в `calendar_events` нет описаний и участников, а события старше вчера удалены.
- Обновить этот файл: статус, PR, хвосты.

**Готово, когда:** сценарий проходит на проде; критерий M1 выполнен.
