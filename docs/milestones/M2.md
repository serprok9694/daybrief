# M2 — Задачи и идеи

> Цель: на дашборде видны задачи на сегодня и просроченные из Google Tasks, а идея, отправленная из Apple Notes через Shortcut, появляется в daybrief.
> Контекст: [`../PRD.md`](../PRD.md) (4.4 идеи, 6.3 поток данных, 6.4 приватность), дизайн — [`../design/README.md`](../design/README.md) («Состояния виджетов», «Командная строка», «Настройки»), макеты — `../design/source/TasksWidget.dc.html`, `IdeaWidget.dc.html`, `Settings.dc.html`. Хвосты M1 — в [`M1.md`](M1.md).
> Каждая задача ниже = один PR. Агент начинает с чтения PRD, design README и этого файла.

## Решения для M2

| Тема | Решение |
|---|---|
| Какие задачи | Все списки задач пользователя (`tasklists.list`). Невыполненные (`showCompleted=false`, `showHidden=false`) со сроком **сегодня или раньше** в таймзоне пользователя. Без срока — не показываем. Подзадачи — обычными строками |
| Срок задачи | Google хранит `due` как дату (время всегда 00:00 UTC, игнорируется). Сравниваем **дату** `due` с сегодняшней датой в `profiles.timezone`: раньше — «Просрочено на N дней», равна — «Сегодня» |
| Что храним (задачи) | Только то, что показывает виджет: id, список, название, дата срока, ссылка `webViewLink`. **Заметки (`notes`) и ссылки-вложения не храним** (PRD 6.4). Каждый sync перезаписывает задачи пользователя целиком |
| Sync задач | Тот же `POST /internal/sync` и тот же job `pg_cron`: для каждого пользователя после календаря — задачи. Тот же refresh token и access token за один проход. `sync_state` с `source = 'tasks'`. Ошибки — по правилам M1 (`invalid_grant` → `revoked`, остальное → `error`, кэш остаётся на экране) |
| Ручное обновление задач | `POST /sync/tasks`, лимит 30 с на пользователя, как у календаря. Чтение — `GET /tasks/today` (просроченные + сегодня, `syncedAt`, ошибка) |
| Идеи: хранение | Таблица `ideas`: текст (до 2000 символов, обрезка пробелов, пустое — 400), источник (`command` / `shortcut` / `reminders`), внешний id (необязательный), хэш нормализованного текста, `created_at`, `snoozed_until`, `done_at`, `last_shown_at`. Дедупликация: уникальность по `(user_id, external_id)` и по `(user_id, text_hash)` среди неархивных — повтор отвечает 200 с существующей идеей, а не 409 |
| `POST /ideas` | Принимает **либо** JWT Supabase (командная строка), **либо** персональный API-токен `Authorization: Bearer dbf_…` (Shortcuts). Тело `{ text, source?, externalId? }`. Ответ `201` (новая) / `200` (дубль) |
| API-токены | Формат `dbf_` + 32 случайных байта (base64url). В БД — только **SHA-256 хэш** и последние 4 символа; полный токен показываем один раз при создании. `last_used_at` обновляется при использовании, «Отозвать» = `revoked_at` (отозванный → 401). Не больше 10 активных токенов на пользователя. Токен даёт доступ **только** к `POST /ideas` |
| Идея дня в M2 | Без LLM (LLM — M4): показываем одну идею — самую давно не показанную среди неархивных и не отложенных; при показе обновляем `last_shown_at` не чаще раза в день, чтобы идея не менялась при каждом открытии. «Не сейчас» → `snoozed_until = now + 7 дней`, «Готово» → `done_at`. Это состояние только в нашей БД (PRD 4.3). В M4 выбор и формулировку под свободное окно делает LLM |
| Командная строка | Enter сохраняет идею через `POST /ideas` (`source: command`) → toast «Идея сохранена», поле очищается. Пустой ввод — ничего не делает. Ошибка — toast с ошибкой, текст остаётся в поле |
| Shortcuts | Не генерируем `.shortcut`-файлы: пошаговая инструкция в `docs/shortcuts.md` — «Send to daybrief» (share sheet + Siri) и ежедневная автоматизация по списку напоминаний «Ideas». Shortcut собирает пользователь |

## T1 — Модель задач и коннектор Tasks

- `packages/core`: тип `GoogleTask` (id, listId, title, dueDate `YYYY-MM-DD`, webViewLink), `TodayTasks` (overdue, today, `syncedAt`, `error`); функции `taskWindow(timezone, now)` (дата «сегодня» и верхняя граница для `dueMax`) и `groupTasks(tasks, timezone, now)` → просроченные (по возрастанию срока) и сегодняшние, с числом дней просрочки.
- `packages/connectors/google-tasks`: чистые функции, `fetch` передаётся параметром: `listTaskLists(token)`, `listDueTasks(token, listId, dueMax)` с пагинацией → `GoogleTask[]` (без `notes` и `links`). `refreshAccessToken` переиспользуется из коннектора календаря (вынести в общий модуль, если нужно).
- Тесты на фикстурах реальной формы ответов Google: задача со сроком сегодня, просроченная, без срока, выполненная, скрытая, подзадача, пагинация; `groupTasks` около полуночи в Europe/Warsaw и UTC, смена DST.

**Готово, когда:** тесты зелёные; в коде коннектора нет сети без переданного `fetch`.

## T2 — Хранение, sync и API задач

- Миграция: `google_tasks` (user_id, list_id, task_id, title, due_date `date`, web_view_link, synced_at; PK user_id+list_id+task_id). RLS: пользователь читает свои строки, пишет только service role. Функции сохранения/ошибки по образцу `save_calendar_sync` / `fail_calendar_sync` (`sync_state.source = 'tasks'`).
- `apps/api`: `syncTasks(userId)`; `syncAll*` обходит календарь и задачи для каждого пользователя (один access token на оба); `POST /sync/tasks` (JWT, лимит 30 с); `GET /tasks/today` (JWT). Итог `/internal/sync` — счётчики по источникам, без данных пользователей.
- Тесты с фейковыми deps: успешный sync, `revoked`, ошибка Google при успешном календаре (и наоборот: один источник не ломает другой), лимит частоты, ни один ответ и лог не содержит токенов и названий задач.

**Готово, когда:** миграция применяется локально; тесты зелёные; после merge следующий запуск job заполняет `google_tasks` автора на проде (проверка — SQL-запрос из PR).

## T3 — Виджет «Задачи»

- По `TasksWidget.dc.html`: группы «Просрочено» (сначала) и «Сегодня», без чекбоксов; просрочка — чип с иконкой `clock` + текст «просрочено на N дней» (ICU `overdueBy`); клик по задаче → `webViewLink` в Google Tasks; «Показать ещё N» после 5 задач (первые 5 по порядку: просроченные, затем сегодняшние).
- Состояния: загрузка (5 строк), пусто («Задач на сегодня нет»), ошибка («Не удалось обновить» + «Повторить»), `error` подключения с кэшем — задачи + пометка, как в виджете событий; `revoked` / нет подключения — переподключиться в настройках. «Обновлено N мин назад», кнопка «обновить» → `POST /sync/tasks`, автообновление при возврате на вкладку, если данным > 5 мин — переиспользовать логику виджета событий, а не копировать.
- Строки — i18n (en + ru); dev-мок: обычный день, только просроченные, пусто, ошибка, много задач.

**Готово, когда:** виджет совпадает с макетом на 1440 и 390 в обеих темах и языках (dev-мок); lint, typecheck, test, build зелёные.

## T4 — Идеи и API-токены (БД + API)

- Миграция: `ideas` и `api_tokens` по таблице решений. RLS: пользователь читает свои строки; `api_tokens.token_hash` клиенту недоступен; пишет только API (service role).
- `apps/api`:
  - `POST /ideas` (JWT **или** API-токен; валидация, нормализация, дедупликация, `201`/`200`);
  - `GET /ideas/today` (JWT): идея дня по правилу M2 или `null`; `POST /ideas/:id/snooze`, `POST /ideas/:id/done` (JWT, только свои);
  - `GET /tokens` (список: id, имя, последние 4, `created_at`, `last_used_at`), `POST /tokens` (возвращает полный токен один раз), `DELETE /tokens/:id` (отзыв). Все — JWT; API-токеном токены не управляются.
- Проверка токена — по хэшу, сравнение за постоянное время; полный токен не попадает в логи и ответы, кроме ответа `POST /tokens`.
- Тесты: JWT и токен для `POST /ideas`, отозванный/чужой/кривой токен → 401, токен не открывает другие маршруты, дедуп по тексту и `externalId`, лимит длины, выбор идеи дня (отложенные и готовые не выбираются, `last_shown_at` раз в день), лимит 10 токенов.

**Готово, когда:** миграция применяется локально; тесты зелёные; на проде `curl` с токеном (созданным через API) добавляет идею.

## T5 — Командная строка, «Идея дня», токены в настройках

- Командная строка: Enter → `POST /ideas` → toast «Идея сохранена» (дизайн: тёмная pill с `check`); ошибка — toast ошибки, текст остаётся. На мобильном — нижняя закреплённая строка, на десктопе — верхняя панель (уже свёрстаны).
- Виджет «Идея дня» по `IdeaWidget.dc.html`: текст идеи, «Не сейчас» (secondary) и «Готово» (primary) → API → следующая идея; пусто — «Запиши первую идею» + подсказка про Shortcut; загрузка, ошибка. Подпись «под свободное окно» из макета в M2 не показываем (это M4).
- Настройки: раздел «API-токены» по `Settings.dc.html` — список (маска `dbf_••••a91c`, «использован …»), «Новый токен» (показ полного токена один раз + «Скопировать»), «Отозвать» с подтверждением, подсказка `POST /ideas`.
- Строки — i18n (en + ru); dev-мок для идеи (есть / пусто / ошибка) и токенов.

**Готово, когда:** на 1440 и 390 в обеих темах и языках совпадает с макетами (dev-мок); lint, typecheck, test, build зелёные.

## T6 — Shortcuts и финальная проверка M2 *(частично делаешь ты)*

- Агент: `docs/shortcuts.md` — пошагово, со скриншот-описаниями действий Shortcuts:
  1. «Send to daybrief»: принимает текст из share sheet (Notes) или спрашивает текст (Siri), `Get Contents of URL` → `POST https://daybrief-api.vercel.app/ideas` с заголовком `Authorization: Bearer <токен>` и JSON `{ "text": …, "source": "shortcut" }`, уведомление «Сохранено».
  2. Автоматизация раз в день: найти невыполненные напоминания списка «Ideas» → для каждого `POST /ideas` с `source: "reminders"` (дубли отсекает сервер).
- Ты: создаёшь токен в настройках, собираешь оба Shortcut на iPhone, отправляешь идею из Apple Notes и из Reminders.
- Сценарий проверки на проде: задачи (сегодня, просроченная, без срока, выполненная) отображаются верно → изменение в Google Tasks видно после «обновить» → идея из Notes через Shortcut появилась → повторная отправка не создала дубль → «Не сейчас» / «Готово» работают → отозванный токен получает 401.
- Обновить этот файл: статус, PR, хвосты.

**Готово, когда:** сценарий проходит на проде; критерий M2 выполнен.
