# M0 — Каркас

> **Статус: закрыт 2026-10-28.** Финальная проверка на проде пройдена: вход через Google → дашборд → настройки (язык, тема, фон сохраняются) → выход.
> PR: T1 #1, T2 #2 + #3 + #8, T3 #5, T4 #6, T5 #4, T6 #7, T7 #9, T8 #10.
>
> Известные хвосты на M1+:
> - env-переменные `daybrief-api` заданы только для Production — вход на preview-деплоях не работает;
> - сохранённые scopes = запрошенные; sync в M1 должен проверять реальный доступ и ставить `status='error'`;
> - до загрузки `/me` тема следует системе — возможна короткая вспышка темы после перезагрузки;
> - выбор языка на экране входа не сохраняется до входа;
> - native-сборки (iOS/Android) не запускались; для них нужен `daybrief://**` в Supabase Redirect URLs.

> Цель: на проде после входа через Google открывается пустой дашборд в утверждённом дизайне.
> Контекст: [`../PRD.md`](../PRD.md), дизайн — [`../design/README.md`](../design/README.md).
> Каждая задача ниже = один GitHub issue = один PR. Агент начинает с чтения PRD, design README и этого файла.

## Решения для M0

| Тема | Решение |
|---|---|
| Пакетный менеджер / монорепо | pnpm workspaces + Turborepo |
| Язык | TypeScript `strict` везде |
| Линт / формат | ESLint + Prettier (стандартные конфиги Expo и TS) |
| Тесты | Vitest для пакетов и API; Testing Library для компонентов, где оправдано |
| Клиент | Expo SDK (последний стабильный), Expo Router, сборка web через `expo export --platform web` |
| Стили | NativeWind v4, цвета через CSS-переменные из `tokens.json`, тема — `vars()` на корне |
| Шрифт / иконки | `@expo-google-fonts/manrope` (400/500/700), `lucide-react-native` |
| i18n | **i18next + react-i18next + i18next-icu** (в `i18n.json` есть ICU-плюрализация); ключи типизированы |
| API | Hono на Vercel, typed RPC-клиент (`hc`) в приложении |
| БД / auth | Supabase (Postgres, Auth, RLS), локально — Supabase CLI, миграции в `supabase/migrations` |
| Шифрование Google-токенов | AES-256-GCM на стороне API, ключ в `TOKEN_ENCRYPTION_KEY` |
| CI | GitHub Actions: lint, typecheck, test на каждый PR |

## T0 — Аккаунты и секреты *(делаешь ты, агент даёт пошаговый мастер)*

Шаги, которые может сделать только человек:
- GitHub: репозиторий `daybrief` (приватный), push текущего `main`.
- Supabase: проект (регион — ближайший EU), включить провайдер Google в Auth.
- Google Cloud: проект, OAuth consent screen в режиме **Testing** (ты — тестовый пользователь), scopes `calendar.readonly`, `tasks.readonly`; OAuth client (Web) с redirect URI Supabase.
- Vercel: аккаунт подключён к GitHub (проекты создаст T2).

**Готово, когда:** в менеджере паролей лежат Supabase URL / anon key / service role key, Google client id / secret; Google-провайдер в Supabase настроен.
Секреты в чат и в репозиторий не попадают.

## T1 — Монорепо и правила проекта

- pnpm + Turborepo; `apps/app` (Expo Router, web запускается), `apps/api` (Hono, `GET /health`), пакеты-заготовки `core`, `connectors`, `ui`, `i18n`.
- Общие `tsconfig`, ESLint, Prettier, Vitest; скрипты `dev`, `build`, `lint`, `typecheck`, `test` на корне через turbo.
- GitHub Actions: lint + typecheck + test.
- `CLAUDE.md`: как устроен репозиторий, где PRD/дизайн/майлстоуны, правила (TS strict, тесты к логике, секреты только в env, строки UI только через i18n, цвета только через токены), команды.
- `.env.example` для app и api.

**Готово, когда:** `pnpm i && pnpm dev` поднимает web-приложение и API локально; CI зелёный.

## T2 — Деплой-конвейер

- Vercel: два проекта — web (`apps/app`, статический export) и api (`apps/api`, Hono). Preview-деплой на каждый PR, prod — с `main`.
- Supabase: связка CLI с проектом, миграции применяются из CI на `main`.
- Документ `docs/deploy.md`: env-переменные каждого окружения, где их задавать.

**Готово, когда:** merge в `main` деплоит web и api; `https://<api>/health` отвечает на проде; у PR есть preview-ссылка.

## T3 — Дизайн-система (`packages/ui`)

- Токены из `docs/design/tokens.json` → `packages/ui/tokens` + конфиг Tailwind/NativeWind (цвета = CSS-переменные), темы light/dark, режим `lite` для Android.
- Тема: `auto | light | dark` (auto = системная).
- Примитивы: `Scene` (фон по времени суток, CSS-градиенты), `Sheet`, `Card` (стекло: web `backdrop-filter`, native `expo-blur` + плашка), `Button` (primary/secondary/ghost, small), `Chip` (neutral/accent soft/solid), `ListRow`, `Avatar`, `Skeleton`, `Toast`, `IconButton` (хит-зона 44).
- Manrope, Lucide; `prefers-reduced-motion` / Reduce Motion отключает анимации.
- Dev-экран `/dev/ui` — витрина компонентов в обеих темах (аналог `Components.dc.html`).

**Готово, когда:** витрина визуально совпадает с `Components.dc.html` и `Tokens.dc.html` в web в обеих темах.

## T4 — i18n (`packages/i18n`)

- i18next + react-i18next + i18next-icu; словари en/ru из `docs/design/i18n.json` (+ строки `settings.theme.*`).
- Типизированные ключи (ошибка компиляции на несуществующий ключ).
- Язык: по системе при первом входе, далее — из профиля пользователя; смена без перезагрузки.
- Тест: все ключи есть в обоих языках; ICU-плюралы (`overdueBy`) корректны для ru (1/2/5 дней).

**Готово, когда:** переключение языка на витрине меняет все строки; тесты зелёные.

## T5 — Схема БД и шифрование токенов

- Миграции: `profiles` (user_id, display_name, locale, theme, scene, timezone), `google_connections` (user_id, scopes, refresh_token_encrypted, status, updated_at). RLS: пользователь видит только свои строки; `refresh_token_encrypted` недоступен клиенту (только service role).
- Триггер: создание `profiles` при регистрации.
- Генерация типов Supabase в `packages/core`.
- В `apps/api`: утилита AES-256-GCM `encrypt/decrypt` + тесты; middleware проверки Supabase JWT; `GET /me` (профиль).

**Готово, когда:** миграции применяются локально и на проде; тесты RLS (чужой профиль недоступен) и шифрования зелёные.

## T6 — Вход через Google

- Экран входа по `SignIn.dc.html` (EN/RU переключатель, пункты о приватности).
- Supabase Auth Google OAuth: scopes `calendar.readonly tasks.readonly`, `access_type=offline`, `prompt=consent`.
- После входа клиент передаёт `provider_refresh_token` в `POST /connections/google` → API шифрует и сохраняет; токен нигде больше не сохраняется.
- Защищённые маршруты: без сессии → экран входа. Выход из аккаунта.

**Готово, когда:** на preview можно войти своим Google-аккаунтом, в `google_connections` лежит зашифрованный токен с нужными scopes, выход работает.

## T7 — Оболочка дашборда

- Раскладка по `Main.dc.html` / `MobileLight.dc.html`: сетка страницы с `--rail-w: 0`, верхняя панель (аватар + имя → настройки; **без колокольчика**), sheet, приветствие по времени суток + дата, сетка карточек (min 340), мобильная колонка с командной строкой внизу.
- Виджеты-заглушки «Сводка, События, Задачи, Письма, Идея дня» в состоянии **загрузка** (skeleton из дизайна) — без данных.
- Командная строка видна, но ввод идей подключается в M2 (в M0 — поле активно, Enter ничего не сохраняет; либо disabled с подсказкой — на усмотрение, без фейкового toast).
- Фон сцены выбирается по локальному времени пользователя.

**Готово, когда:** дашборд в web на 1440 и 390 совпадает с макетами в обеих темах и обоих языках.

## T8 — Настройки и финальная проверка M0

- Экран по `Settings.dc.html`: язык, **тема (Авто / Светлая / Тёмная)**, фон (Авто + 4 сцены), подключённые аккаунты (Google Календарь + Задачи — статус; Gmail — «скоро», кнопка неактивна до M3). Раздел API-токенов скрыт до M2.
- Изменения сохраняются в `profiles` и применяются сразу.
- Финальная проверка M0 на проде: вход → дашборд → настройки → смена языка/темы/фона → выход.

**Готово, когда:** сценарий выше проходит на проде; критерий M0 выполнен.
